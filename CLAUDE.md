# CLAUDE.md — AI Memory Reader

## Repository Overview

AI Memory Reader (AIMR) is a native macOS 15+ / iOS 17+ SwiftUI app for reading, browsing, and lightly editing the memory files that AI coding agents leave on disk. It auto-discovers 8 AI agent directories (Claude Code, Codex, Gemini, Cursor, Continue, GitHub Copilot, Aider, OpenClaw), renders Markdown and JSONL with GitHub-style formatting, and watches files live as agents write them.

- **Bundle ID:** `com.aitools.ai-memory-reader`
- **Current version:** 0.4.6 (build 9 macOS, build 7 iOS)
- **License:** GPL-3.0
- **Distribution:** Direct-download (GitHub Releases, ad-hoc signed) + Mac App Store (sandboxed)
- **Repo:** https://github.com/nvwalj/ai-memory-reader

## Build & Development Setup

### Prerequisites

- macOS 15.0+, Xcode 16.0+, Swift 6.0
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) 2.40+

```bash
brew install xcodegen
```

### Generate and open the project

```bash
cd ai-memory-reader
xcodegen generate          # regenerates AIMemoryReader.xcodeproj from project.yml
open AIMemoryReader.xcodeproj
```

Press **Cmd+R** to build and run. There are no tests (the project has no test targets).

### Regenerate after editing project.yml

Any change to `project.yml` (new source files, new SPM package, entitlements, build settings) requires re-running `xcodegen generate` before Xcode sees it.

### SPM dependencies (resolved automatically by Xcode)

| Package | Version | Purpose |
|---------|---------|---------|
| [swift-markdown-ui](https://github.com/gonzalezreal/swift-markdown-ui) | 2.4.x | GitHub-style Markdown rendering |
| [Splash](https://github.com/JohnSundell/Splash) | 0.16.x | Syntax highlighting for code blocks |

### Two build configurations

- **Debug** — `CODE_SIGN_ENTITLEMENTS = ""` (unsandboxed). No Gatekeeper, no sandbox prompts. Use this for day-to-day development.
- **Release** — uses `AIMemoryReader.entitlements` (sandboxed, for Mac App Store). `BookmarkStore` code paths activate in this configuration.

### CLI tool (optional)

```bash
cp aimr /usr/local/bin/
chmod +x /usr/local/bin/aimr
aimr open /path/to/file.md --heading "Section Name"
```

## Architecture & Key Patterns

### State management

`AppState` is the single `@Observable` root object, injected via `.environment(appState)` at the `WindowGroup` level. All views read it through `@Environment(AppState.self)`. There is no ViewModel layer — views bind directly to `AppState` properties using `Bindable(appState)`.

### Platform split

All macOS-only code is guarded with `#if os(macOS)`. iOS gets a simplified read-only `NavigationStack` layout. Both targets compile from the same source tree (`AIMemoryReader/Sources`); `project.yml` lists the same `sources` path for both targets.

### File tree

`FileTreeBuilder.buildTree(at:strictFiltering:)` builds a `FileNode` tree recursively. When `strictFiltering: true` (the default), `MemoryFileMatcher.isLikelyMemory()` gates which files appear — `.md`/`.mdc`/`.jsonl` always pass; `.json`/`.yaml`/`.yml` only pass if the filename is in a known set (e.g., `config.json`, `claude.md`). The "Show All JSON/JSONL Files" menu toggle switches to `strictFiltering: false`.

### File watching

`FileWatcher` wraps FSEvents. It posts `Notification.Name.fileWatcherDidDetectChange`. `AppState` subscribes, debounces 500ms, then calls `handleFileSystemChange()` which rebuilds the tree while preserving expanded-directory state and the current selection.

### JSONL rendering

`DetailView.prettyPrintJSON` handles both single-object JSON and JSONL (one object per line). Large JSON is chunked into `MarkdownSection`s of ~30 lines / 3000 chars to avoid a stack-overflow in MarkdownUI's recursive `Text` concatenation (observed at ~5000 nodes).

### Theming

`AppTheme` has two values: `.standard` (system light/dark) and `.eyeCare` (Solarized palette). `ThemePalette.resolve(theme, colorScheme)` produces a `ThemePalette` struct that propagates through the view hierarchy via `EnvironmentValues`. The MarkdownUI theme (`Theme.memoryReader(palette:)`) is built from the palette.

### Settings persistence

`SettingsStore` writes to both `NSUbiquitousKeyValueStore` (iCloud) and `UserDefaults.standard` simultaneously (iCloud-first read). On launch it restores iCloud values locally and migrates legacy UserDefaults keys once.

### Sandbox / BookmarkStore

The Mac App Store build is sandboxed. `BookmarkStore` persists security-scoped bookmarks for the user's home folder so the app can read `~/.claude/`, etc. across launches. The direct-distribution (GitHub ZIP) build is *not* sandboxed — `BookmarkStore.isSandboxed` is false and the bookmark code paths are skipped entirely.

### URL scheme

`aimemoryreader://open?path=<encoded-path>&heading=<encoded-heading>` is handled in `AIMemoryReaderApp.onOpenURL`. Path traversal (`..`, non-absolute paths) is rejected. The `aimr` shell script wraps this scheme for CLI use.

### Update checker

`UpdateChecker.shared` polls `https://api.github.com/repos/nvwalj/ai-memory-reader/releases/latest` once per app session (skipped for sandboxed/MAS builds). Compares semver with the running bundle's `CFBundleShortVersionString`. Shows a dismissible `UpdateBanner` at the top of the window.

## AI Source Auto-detection

`AISource.allSources` is a static array of 8 known sources. `detectAvailable()` filters to those where the directory exists *and* contains at least one supported file. Custom sources are stored in `SettingsStore.customAISourcePaths` and loaded via `loadCustomSources()`.

## Notable Specifications / Planned Features

### `CLAUDE_CLOUD_MEMORY_SPEC.md`

Spec for surfacing the user's claude.ai *cloud* memory (the "saffron" consumer memory feature) inside AIMR. Key design decisions:

- Auth via embedded `WKWebView` one-time login; cookies held in `WKHTTPCookieStore`, never written to disk.
- Reads `GET /api/organizations/{org_id}/memory` — plain Markdown blob, 1–4 KB.
- `org_id` discovered via `GET /api/bootstrap`.
- New sidebar group `Claude.ai (Cloud)` next to local groups.
- Memory fetched on-demand; never persisted unless user explicitly saves a snapshot.
- v1 scope: read-only account memory. v2: project-level memory, write-back.
- Implementation lands primarily in `AppState.swift`, `AISource.swift`, and a new `CloudMemoryService.swift`.

## Notes for AI Assistants

- **No tests.** There are no XCTest targets. Manual testing via Xcode Simulator or device is the only verification path.
- **Do not edit `AIMemoryReader.xcodeproj/` directly.** Edit `project.yml` and re-run `xcodegen generate`.
- **Swift 6 strict concurrency is enabled** (`SWIFT_STRICT_CONCURRENCY: complete`). New code must respect `Sendable`, `@MainActor`, and structured concurrency. Async work that touches UI must be dispatched back to `@MainActor`.
- **Platform guards are everywhere.** When adding new functionality, check whether it uses `AppKit`, `FSEvents`, `NSOpenPanel`, `NSPrintOperation`, or `WKWebView` — all macOS-only. Wrap with `#if os(macOS)` as appropriate.
- **`AppState` is `@MainActor`.** All mutations happen on the main actor. Background work (file I/O, search) is dispatched with `DispatchQueue.global` or `Task`, then results are applied back on `MainActor`.
- **`@Observable` macro, not `ObservableObject`.** `AppState` and `FileNode` use the `@Observable` macro (Swift 5.9+). Use `Bindable(appState).property` for two-way bindings, not `$appState.property`.
- **File filtering has two modes.** The default strict mode hides noise like `package.json`. When implementing features that enumerate files, use `FileNode.isSupportedFile(url, strict: true/false)` or `MemoryFileMatcher.isLikelyMemory(url)` as appropriate — don't add bare extension checks.
- **Sandbox-aware path resolution.** Never hardcode `FileManager.default.homeDirectoryForCurrentUser` for source paths in sandboxed builds — it resolves to the container. Use `AISource.url` which delegates to `BookmarkStore.shared.userHomeURL` when sandboxed.
- **Settings go through `SettingsStore.shared`.** Never write directly to `UserDefaults.standard` for user-facing preferences — the iCloud sync layer will miss it.
- **JSON chunking is intentional.** The 30-line / 3000-char chunk limit in `makeJSONSections` is a crash guard, not a performance hack. Do not remove it without understanding the MarkdownUI recursive `Text` issue.
- **The `aimr` script is user-installed separately.** It is not bundled inside the `.app`. Users copy it to `/usr/local/bin` manually.
- **Update checker is skipped for MAS/sandboxed builds.** `UpdateChecker.checkIfDue()` is a no-op when `BookmarkStore.isSandboxed` is true; Apple handles MAS updates.
